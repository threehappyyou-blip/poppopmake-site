JSON Formatter

Formats messy JSON into a clean, readable, indented structure — or minifies it down to a single compact line — and checks it's valid along the way.

  1. Paste your JSON into the "Paste JSON" box (it starts with a small example you can replace).
  2. Choose the indent size. "2 spaces" (the default) or "4 spaces" pretty-prints it with indentation; "Minify (no spaces)" squeezes it onto one line.
  3. Click "Format." The formatted version appears in the "Result" box below. A green message says "Valid JSON, formatted below."
  4. Check for errors. If your JSON isn't valid, a red message says "Not valid JSON" and points to the line and column where the first problem is (for example, Expected ',' or '}' at line 3, column 5), instead of just failing silently. The Result box stays empty until the problem is fixed.
  5. Copy the result with the "Copy result" button.
Good to know: A common cause of "invalid JSON" errors is a trailing comma after the last item in an object or array, or single quotes instead of double quotes — both fine in JavaScript, but not in strict JSON. Another thing to watch: if your JSON has a whole number larger than 9,007,199,254,740,991 (253), such as a long ID, JavaScript can't store it exactly. The tool still formats it, but adds a warning that the value may have changed — keep IDs like that as strings.

Tab 2

Base64 Encode/Decode

Converts text to and from Base64 encoding, correctly handling non-Latin text and emoji.

  1. To encode: type or paste plain text into the "Text" box and click "Encode →." The Base64 version appears in the "Base64" box below.
  2. To decode: paste a Base64 string into the "Base64" box and click "← Decode." The plain text appears in the "Text" box above. If the Base64 box is empty, the tool says so and leaves your text untouched.
  3. Pick the style (optional). Tick "URL-safe output" to encode with - and _ instead of + and /, and no trailing = padding — the form used in web addresses and tokens. You don't need to tick anything to decode URL-safe Base64: the tool spots it and converts it automatically, and tells you it did.
  4. Copy the result with the "Copy result" button, which copies the Base64 box.
Good to know: Some simpler Base64 tools break on non-English text or emoji because of how they handle character encoding — this one is built to handle UTF-8 correctly, so Korean, Japanese, emoji, and other non-Latin characters round-trip through encode and decode. If you decode something that isn't valid text (for example, Base64 of an image or a file), the tool warns you that the result may be corrupted, because it can't be shown as readable text.

Tab 3

UUID Generator

Generates UUIDs (universally unique identifiers) — random, time-based, or sortable — one at a time or in a batch.

  1. Choose a version. "v4 — random" is the default and the right choice for most uses. "v1 — time-based" is built from the current time. "v7 — sortable (time-ordered)" starts with a timestamp, so UUIDs created later sort after earlier ones — handy for database keys.
  2. Get one UUID. A UUID is already shown when the page opens. Click "Generate new UUID" for another, and "Copy" to copy it.
  3. Or get a batch. Under "Generate multiple," enter how many you need (1 to 100) and click "Generate list." A message confirms how many were made; if you ask for more than 100, you get 100 and the message says so.
  4. Copy the batch with "Copy all," which puts one UUID on each line.
Good to know: Each UUID is generated independently using your browser's secure random source, so even a batch carries no meaningful risk of a duplicate. The version you pick applies to both the single UUID and the batch. Browsers can't read a computer's hardware address, so v1 UUIDs use a random value in its place, as the standard allows.

Tab 4

Color Converter

Converts a color between HEX, RGB, and HSL formats, with a live preview swatch — and checks how readable text in that color is against another color.

  1. Enter a color. Type a HEX code into the HEX box, or click the small color square beside it to pick one visually. A HEX code can be typed with or without the "#", in short form (#0d7) or long form (#0D7A7C), and with an alpha (transparency) part like #0D7A7C80.
  2. Read the converted values. The HEX, RGB, and HSL versions appear below the swatch, updated as you type. With an alpha part, they appear as rgba(…) and hsla(…).
  3. Copy a value with the "Copy" button on its row.
  4. Check text contrast (optional). Under "WCAG contrast check," choose the color to compare against (white by default) — type a HEX code or use its color square. The tool shows the contrast ratio and whether the pair passes the AA and AAA accessibility levels for normal and large text.
Good to know: If you type something that isn't a valid HEX color, a red message shows the accepted forms, and the last good values stay on screen until you fix it. The contrast check ignores transparency and compares the opaque colors, and says so when you've entered an alpha part. As a rule of thumb, body text should reach at least 4.5:1 to pass AA.

Tab 5

URL Encode/Decode

Percent-encodes text for safe use in a URL, or decodes an already-encoded string back to readable text.

  1. To encode: type or paste text into the "Text or URL" box and click "Encode →." The encoded version appears in the "Result" box below.
  2. To decode: paste the encoded text into the "Result" box and click "← Decode." The readable text appears in the "Text or URL" box above. If the Result box is empty, the tool says so and leaves your text untouched.
  3. Copy the result with the "Copy result" button.
Good to know: This is most often needed for putting special characters (spaces, &, ?, #) safely into a query-string value — encode just that value, not the whole URL, because encoding a full address would also escape the slashes and colons that need to stay as they are. If your input already contains codes like %20, the tool warns that encoding it again will double-encode it (%20 becomes %2520); decode it first if that isn't what you want. Decoding text with a broken % code gives an "invalid" message instead of garbage.

Tab 6

Dummy Data Generator

Generates fake but realistic-looking test data — names, emails, phone numbers, addresses — for testing an app or filling in a demo.

  1. Choose how many rows in "Number of rows" (1 to 200; a table of 10 is generated when the page opens).
  2. Choose which fields you need. Tick First name, Last name, Email, Phone, Address, Company, and/or Username. The first five are ticked to begin with; you need at least one.
  3. Click "Generate." A preview table shows your rows. If you ask for more than 200 rows, you get 200 and the message says so.
  4. Copy the data. Click "Copy as CSV" or "Copy as JSON" to copy exactly the rows and fields shown, ready to paste into a spreadsheet, a file, or your code.
Good to know: Every value is randomly made up — the names, street addresses, and (US-style) phone numbers are put together from lists and random digits, and nothing is saved or sent anywhere. Because they're random, a generated email address or phone number could coincidentally belong to a real person, so use the data for test databases and mock-ups, never to send real email or make real calls. For test emails that must not reach anyone, use addresses at example.com instead.
